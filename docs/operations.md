# 部署与维护

## Docker

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 worker
```

`dashboard` 负责 FastAPI 与前端静态页面；`worker` 独立运行行情、策略、风控、公司行动和撮合。数据库唯一位置为命名卷中的 `/data/niuno3.sqlite3`。Compose 默认项目 `niuno3`，卷逻辑名 `niuno3-data`，实际名称 `niuno3_niuno3-data`。只有 dashboard 映射 `127.0.0.1:8789`。容器以非 root 用户运行，Docker 日志限制 3 × 10MB。

普通停止保留账本：

```bash
docker compose down
```

再次 `up -d` 自动读取已有账户、配置、订单和计划。**不要对正式项目使用 `down -v`**，该命令会删除账户数据卷。

### Cloudflare Tunnel 公网部署

公网入口为 <https://niualpha.com>，流量路径为 Cloudflare → 本机 `cloudflared` → `http://localhost:8789` → dashboard。Cloudflare 已启用「始终使用 HTTPS」，HTTP 请求自动跳转到 HTTPS。仍由现有 Docker 命名卷保存账户、配置和交易记录，公网登录使用同一管理密钥。

本机复用 Cloudflare 账户中的 **mac mini stock page** 隧道（`c3f86c62-7e88-4148-97e8-bc3d7868c52d`），在 Cloudflare **联网 → Tunnels → 应用路由** 中管理。`niualpha.com` 对应 `http://localhost:8789`；原有 `niuone.cn` 继续对应 `http://localhost:8787`。DNS 使用代理状态开启的 CNAME，指向该隧道的 `.cfargotunnel.com` 地址。配置保存在 Cloudflare，无需将隧道令牌写入此仓库。

在 `.env` 设置可信代理来源，确保同源校验、HTTPS 会话 Cookie 与登录限流使用正确的协议和客户端地址：

```dotenv
NIUNO3_TRUSTED_PROXIES=127.0.0.1,172.19.0.1
```

`172.19.0.1` 是本次部署实际观察到的 Docker 网络网关。换主机或重建网络后，用 `docker network inspect niuno3_default` 与 dashboard 访问日志核对并更新；不要设为 `*`。默认留空时不信任任何转发头。宿主机端口继续只绑定 `127.0.0.1`，避免绕过 Cloudflare 直接从外网连接。

更新应用与检查公网：

```bash
docker compose up -d --build --wait
curl --fail https://niualpha.com/healthz
docker compose ps
```

本机 `cloudflared` 由现有 macOS 服务维持运行，Docker 容器使用 `unless-stopped` 自动重启。本机必须保持开机、联网，Docker Desktop 也须处于运行状态；Mac 关机、休眠或 Docker 停止期间公网服务不可用。

路由设置参考 [Cloudflare Tunnel 官方文档](https://developers.cloudflare.com/tunnel/routing/)。

### 设置页面密码验证

未设置环境密码时，密钥随机生成在 `/data/admin-token.txt`，权限 0600。可用 `docker compose exec dashboard cat /data/admin-token.txt` 读取并在页面输入。自定义密码在首次启动前通过 `.env` 设置，后续修改环境变量不会覆盖数据库中的身份凭据。

投资总览（含账户与交易记录）、我的 ETF、策略信号可以直接查看。进入 **设置与运行** 需要验证管理密码；添加／移除 ETF、保存配置、发送测试通知和修改密钥等所有变更操作也需要验证。未验证时会弹出密码框，验证成功后继续原操作，关闭密码框则取消操作。验证后在有效会话内无需重复输入，退出或会话过期后需重新验证。

验证后在 **设置与运行 → 管理密钥** 页签修改，也可直接访问 `/settings#admin-security`。填写当前管理密钥、新管理密钥和确认新管理密钥，点击“保存密钥并重新登录”。密码必填，不限制长度和字符组合；新密钥需与确认值一致且不同于当前密钥。初始化密码同样不限制长度和字符组合。修改立即生效，所有设备的原会话失效，使用新密钥重新进入设置即可，无需重启服务。

新密钥只保存加盐 scrypt 哈希，不回显、不写入运行日志或明文文件。原 `admin-token.txt` 在成功修改后清理；该文件仅用于首次登录。若文件权限导致清理失败，页面提示手动清理，数据库中已生效的新密钥不受影响，旧文件内容无法登录。`NIUNO3_ADMIN_PASSWORD` 仍仅供初始化，重启不会恢复旧密钥。凭据更新、会话撤销和不含密钥内容的审计记录在同一事务提交；修改失败保留原凭据。

会话保存为 HttpOnly、SameSite=Strict cookie，HTTPS 环境额外启用 Secure，12 小时过期。SQLite 只保存密钥的 scrypt 哈希及会话令牌哈希；同一来源 10 分钟内最多 10 次失败登录。设置相关接口（参数、通知、运行记录、管理密钥）和所有变更接口均需会话，后端会拒绝未登录或会话失效的变更请求。所有写操作还要求同源与 `X-NiuNo3-Request: 1` 请求头。退出或会话失效不影响其他页面的数据展示。

修改密钥时核验当前密钥，与登录共享上述失败次数限制。当前密钥错误返回 400，登录已失效返回 401，输入不符合要求返回 422，超出尝试次数返回 429；认证接口的格式校验错误不会回显输入值。行情下载和 worker 不依赖浏览器会话，修改密钥不会暂停采集或变更交易参数。

## 本地开发

Python 3.11+，验收使用 3.12。Node 22.12+ 或兼容的 Node 24+，pnpm 11.19.0。

裸 K 策略的 Python worker 通过 Node 调用与图表相同的价格行为引擎。Node 不仅用于前端构建，worker 运行期间也须可从 PATH 调用；Docker 镜像已包含。结构计算按输入缓存、批量运行，并设 45 秒超时，失败时等待有效信号。

```bash
uv sync --locked --python 3.12
pnpm --dir web install --frozen-lockfile
pnpm --dir web build
uv run python -m app.entrypoints.dashboard
```

在另一终端启动：

```bash
uv run python -m app.entrypoints.worker
```

本地默认数据目录 `.local-data/`，不会读取 Docker 卷。前端开发服务器用 `pnpm --dir web dev`，Vite 将 `/api` 代理至本地后端 8789；健康检查直接访问后端端口。部署版由 FastAPI 同源提供页面，无额外前端端口。

依赖更新后同步锁文件：

```bash
uv lock
uv export --frozen --no-dev --no-hashes --format requirements-txt -o requirements.txt
pnpm --dir web install
./scripts/validate.sh
```

## 运行状态

| 入口 | 含义 |
| --- | --- |
| `GET /healthz` | Web 进程与数据库可访问，正常返回 200 |
| `GET /readyz` | 交易数据、日历、心跳和账本检查，未就绪返回 503 及原因 |
| `GET /api/v1/status` | 相同就绪信息，加自动运行、暂停、等待原因和开市状态 |
| worker healthcheck | 心跳超过 30 秒或数据库不可读视为失败 |

首次启动 `healthz=200, readyz=503` 是正常的数据预热状态。看板会展示目录、分类、可交易基金和历史数据数量。工作线程持有可过期数据库租约，重复启动 worker 只允许一个进程调度；网络请求在有界线程池中运行，避免阻塞撮合循环。

公开源出错时保留旧快照，等待后续有界重试。覆盖率不足禁止买入，已有持仓仍可在盘口及公司行动核验通过时执行风险退出。连续失败可在“设置与运行 → 数据与运行”查看下载进度、就绪原因和任务记录；运行记录每页 10 条，可翻页或刷新。

### 日历更新

`config/calendar.json` 明确覆盖起止日期、交易所公告来源和核验日期。当前覆盖至 2026-12-31。取得下一年正式休市公告后扩充 `end` 和 `closed`，保留旧日期，运行日历与 T+1 测试，再重建两个容器。系统不会用自然工作日代替未知交易日。

### 持续自动运行

系统默认持续自动运行，不依赖页面保持打开或管理会话有效。休市、行情过期、网络中断、数据预热和核算未就绪时持续等待与检查；条件恢复后在有效交易窗口自动执行，无需再次点击恢复。`GET /api/v1/status` 的 `automation` 提供运行状态与等待原因；数据就绪与是否启用自动运行分开表示，后台心跳中断会单独标明。

系统不提供手动启动、暂停或恢复功能，旧 `POST /api/v1/automation/{action}` 接口已移除。升级时清理旧人工暂停标记，后台持续自动检查；账本、有效行情、公司行动、T+1、仓位和信号等检查仍在交易时执行。清理过程保留账户、配置、名单、订单、成交、历史控制记录及风险退出意图，不重放已取消订单，也不改写净值高点。

组合实际回撤仅作统计，不触发保护或限制交易。升级会清理旧组合回撤锁存状态；旧配置中的 `drawdown_stop` 只在读取历史记录时忽略，不再出现在配置界面或参与执行。历史配置、成交与已取消订单保持原始证据，不重放历史订单。历史控制记录继续保留，配置更新仍写入运行记录。

模拟成交不再额外叠加滑点，买入采用卖一价、卖出采用买一价，并按最小价位取整。旧配置中的 `slippage_bps` 读取时忽略，不修改历史配置、成交、费用与账本；新成交及仍待撮合订单均使用当前的无额外滑点规则。此类撮合逻辑更新须同时部署 dashboard 和 worker。

参数保存会生成新版本并取消未完成的普通调仓、盘中调仓与做 T 单，终止旧参数的做 T 轮次并重新确认目标。风险退出保留。已有任何订单后不允许改写初始资金。没有手工篡改持仓、清空账本或覆盖历史的 API。

### 账本核对和备份

```bash
docker compose exec dashboard python -m scripts.audit
docker compose exec dashboard python -m scripts.audit --backup /data/backup-20260907.sqlite3
mkdir -p backups
docker compose cp dashboard:/data/backup-20260907.sqlite3 ./backups/
```

备份使用 SQLite 在线 backup API，在一致的快照中读取 WAL 数据；目标已存在则拒绝覆盖。备份含账户和登录哈希，应按私有文件保存。仅复制一个正在写入的 `.sqlite3` 文件会漏掉 WAL 中的提交。

### 明确授权的历史滑点修复

仅在用户明确要求修复历史模拟成交时，使用 `scripts.repair_historical_slippage`；普通部署和启动不会运行此工具。默认只读生成逐项修复清单，按保留的原始盘口和旧配置核验历史滑点，保留成交 ID、订单、时间、方向、数量与决策依据。按原订单累计佣金和可卖批次 FIFO 重建成交金额、费用、已实现盈亏、资金分录及剩余持仓成本；历史净值保留原市值及应收估值，只同步现金差额。净值高点没有历史时间戳，因此回撤基准明确按已保存的有效净值和本金重新计算，不推测未记录的盘中峰值。历史风险高点和结构价位不重放。

工具拒绝缺失报价、旧价格无法解释、账本不平衡、待撮合订单、持有期间公司行动、独立风险成本调整或不匹配的估值时间线。执行前在备份副本演练，暂停 worker 后重新生成清单。以下 `26` 为本次明确核对的成交边界；其他修复必须使用实际审核的边界。

```bash
docker compose stop worker
docker compose exec -T dashboard python -m scripts.repair_historical_slippage --through-fill-id 26 --report /data/repair-preview.json
# 使用上一步输出的 source_sha256，报告与备份路径必须尚不存在
docker compose exec -T dashboard python -m scripts.repair_historical_slippage --through-fill-id 26 --report /data/repair-applied.json --apply --expected-sha256 SOURCE_SHA256 --backup /data/backup-before-repair.sqlite3
docker compose exec -T dashboard python -m scripts.audit
docker compose up -d --no-deps --wait worker
```

写入前必须匹配清单指纹，并在数据库写锁内通过另一个只读连接生成独立完整备份，检查备份与源数据一致。只在同一事务内临时解除成交及资金更新触发器，修复后恢复原触发器、验证逐行差异、外键、数据库完整性及账本平衡；任何失败整体回滚。`ledger_repairs` 永久保存完整修改前后值、修复策略、时间和备份位置，`runs` 保存摘要；原始配置、报价、通知和交易决策保持原证据，不重发历史通知。再次运行已修复范围不再改变数据。

恢复时先停止两个服务并备份原卷，使用维护容器把已核验的备份复制到卷中 `/data/niuno3.sqlite3`，移走对应旧 WAL／SHM，保留 UID 10001 的权限，再启动并运行核对。不要在 worker 运行时替换数据库；核对失败不能通过直接修改批次、资金或成交表解除。

原始行情保留最近 7 天；长假期间额外保留最近交易日的全部报价，直到下一交易日开盘，避免分时图跨假期缺失。永久保留每笔成交的报价及前一成交量样本、订单最后报价和每只最新两个样本。普通任务日志保留 30 天，决策和控制日志、完整计划输入、净值和交易账本保留。清理在收盘后或休市日每天至多一次执行；SQLite 复用空闲页，不在盘中 VACUUM。

## API v1

| 方法与路径 | 内容 | 会话 |
| --- | --- | --- |
| `POST /auth/login`、`GET /auth/session` | 登录、状态 | 登录入口公开 |
| `POST /auth/logout` | 注销 | 是 |
| `POST /auth/password` | 修改管理密钥；输入 `current_password/new_password/confirm_password`，成功后全部会话失效 | 是 |
| `GET /status` | 数据覆盖、心跳、自动状态 | 否 |
| `GET /etfs` | 手动 ETF 名单，`q/category/tradable/sort/offset/limit` 只查询与排序已有名单 | 否 |
| `GET /etfs/suggestions?q=沪深300` | 最多 10 条代码／名称提示，已有资料与东方财富按需联想合并；只读，不加入名单 | 否 |
| `POST /etfs` | `{ "code": "510300" }` 手动添加并核验 ETF，重复添加幂等 | 是 |
| `DELETE /etfs/{symbol}` | 从手动名单移除；有持仓或待成交订单时返回 409 | 是 |
| `GET /etfs/{symbol}` | 属性、报价、前复权历史 | 否 |
| `GET /etfs/{symbol}/live-candle` | 当日开高低收、累计量额及来源时间；按上一交易日前复权价对齐，仅用于显示 | 否 |
| `GET /etfs/{symbol}/intraday` | 独立分时展示：分钟价格、昨收、来源交易日、更新时间与延迟状态；默认接受已知活跃 ETF。传入 `day=YYYY-MM-DD` 时只读该日已保留报价，允许查询有成交记录的历史 ETF，缺失返回空点集 | 否 |
| `GET /signals` | 默认按执行方式返回当前目标；`mode=daily` 查看收盘计划，`mode=live` 返回实时目标、新鲜度及 `execution` 盘中动作／等待原因 | 否 |
| `GET /signals/history`、`GET /signals/history/{plan_id}`、`GET /signals/{symbol}/chart` | 信号历史与图表 | 否 |
| `GET /account` | 现金、持仓、可卖数量、收益及净值序列 | 否 |
| `GET /orders`、`GET /trades`、`GET /actions` | 订单、成交、分红折算；`/trades` 支持 `symbol=sh510300` 按标的筛选并返回对应总数，分页最多 200 条 | 否 |
| `GET /t-strategy` | 做 T 周期、后台状态、当前持仓及展示交易日已卖出 ETF 的分钟支撑压力、轮次及执行等待原因；只读，不发起行情下载或交易 | 否 |
| `GET /runs` | 运行日志 | 是 |
| `GET /config`、`PATCH /config` | 参数、标签、版本；保存新版本 | 是 |

上表路径均在 `/api/v1` 下。报价包含 `at/fetched_at/source/stale/quality/status`；`quality` 为 `valid/stale/unknown`。金额在 API 中为元，涨跌幅和比例为小数。API 文档端点未对外启用，接口定义见 `app/dashboard/api.py`。

「我的 ETF」列表及详情的报价额外返回 `display.status/label/warning`，按已核验交易日历显示盘中、午间休市、已收盘或最近交易日状态。休市报价须属于期望交易日，并更新至对应时段末（90 秒容差）；旧交易日、过早的报价、异常价格或未知日历仍提示待更新／待核验。原始 `stale/quality` 和交易有效期不变。界面「行情源时间」保留来源返回的 `at`，悬停可查看采集时间 `fetched_at`；盘后后台每 15 分钟检查行情，来源时间戳可能继续变化，不表示该时刻有成交。

ETF 列表及详情包含 `focus_group/focus_label/amount20/turnover20/turnover_reason/representative/representative_symbol/liquidity_rank/focus_reason`。`turnover20` 使用比例值（0.01 = 1%），缺失为 null，`sort=turnover20` 降序且缺失排最后。列表 `focus` 提供 `minimum_amount/minimum_turnover` 两项门槛及分组、代表、换手率不足和待齐数量。代表在所选候选范围内满足两项门槛后确定，再应用搜索和分页，搜索非代表不会让它成为临时代表。`PATCH /config` 可保存两项下限，0 分别表示不限制。

### 买卖观察

非交易日及下一交易日开盘前，页面展示最近一个已开盘交易日的信息，并标明具体日期。`GET /status`、`GET /account` 的 `display_day` 与 `GET /t-strategy` 的 `day` 使用同一交易日历口径；后者的 `at` 保留实际读取时间。资产走势截至该展示交易日，后台估值记录仍完整保留。分时买卖点保留该交易日已卖出的 ETF，分钟 T 参考价使用该日最后已采集的完整分钟结构，休市期间不因时间流逝消失，开盘后切换新交易日。交易执行仍使用实际时间和原有新鲜度检查；缺失的分钟行情不补造。

界面中的证券代码统一仅显示六位数字，保留前导零；列表、卡片、图表、成交与分红记录、搜索提示、确认弹窗及运行日志均采用同一展示规则。行情请求、路由参数、查询匹配和账本继续使用带交易所前缀的原始标识，展示格式不会改写正式数据。

投资总览「最近成交」默认以「分时买卖点」展示紧凑卡片，最近交易的 ETF 各占一张，桌面最多四列、窄屏两列、手机单列，默认先显示四只，可继续展开。每张图默认选择该 ETF 最近一次成交日，可切换至其他有成交的日期。点击图表空白处、分时线或「放大」可在弹窗中查看大图；放大图保留当前交易日、全部成交标记与 T 参考价，并可切换交易日。点击成交标记仍打开成交明细；关闭明细返回大图，点击「关闭」或按 Esc 收起大图。大图与卡片共用行情及刷新，不额外发起分时轮询。分时线绘图区通常高 124px，横轴固定为 09:30—15:00 并压缩午休；以昨收为参照展示未复权价格，左侧显示价格 Y 轴、刻度与元单位，并以清晰的水平实线标出昨收对应的 0% 轴；切换成交日时零轴随该日昨收更新。买卖标记按实际成交时间贴合分时线；蓝线与标记共用北京时间坐标，已保存报价使用精确到秒的来源时间。标记表示交易发生在曲线上的时间位置，标签和明细保留实际成交价，不把曲线定位价写入账本。每个标记直接显示买卖方向、精确到秒的时间、实际成交价（多笔为均价）、成交份数和金额（元，保留两位小数，不含费用），使用虚线连接对应曲线点。相同委托内同一分钟、同一持仓动作的分笔成交合并为一个点，其份数与账本成交金额对应汇总；缺少账本金额时才由成交价乘份数计算。标签自动错开并避开成交点，相邻成交优先按时间顺序排布；布局后交换发生交叉的标签位置，消除成交连接线之间的交叉，成交锚点仍固定在对应成交时间的曲线上。过密时增加绘图区高度，不隐藏早先标记；点击可查看逐笔成交详情。图下只保留所选日期最近一次成交的一行摘要。「成交时间线」切换保留原列表。

卡片调用带 `day` 的分时接口，只读已采集并保留的全部有效盘中报价，按来源时间逐点绘制，不再合并为每分钟一点；同一来源时刻的重复记录采用最后一条有效报价，价格相同但时间不同的报价仍保留。采样间隔取决于实际采集，当前持仓优先采集间隔为 30 秒，普通名单为 60 秒，多路采集可能产生更短间隔；这不等同于固定 30 秒线或逐笔行情。原始报价通常保留最近 7 天，清理后仍可能有永久保留的成交相关样本。按压缩午休后的交易分钟判断采样连续性：相邻有效采样之间最多缺失一分钟时保持连线，正常连接午盘收盘与下午开盘，不因来源报价的秒数差异误断；连续缺失两个或更多交易分钟及无效采样仍断开。成交标记使用相同的交易时间坐标在线段内部定位，不外推，不跨行情缺口，也不为休市时段生成报价或成交标记。早于首条、晚于末条或处于缺口的成交保留图下明细入口，并注明暂无连续行情。缺少行情时明确提示，不用其他日期或成交价格补造分时。行情与成交必须属于同一交易日；当日卡片在开市时每 30 秒刷新，历史日期固定读取，切换或收起卡片停止其刷新。该接口不写行情库，也不改变策略、撮合或 worker 采集行为。

切换至「成交时间线」后，按北京时间和最近成交倒序展示日期、时间、买卖方向、ETF 名称／代码、成交份额与价格；桌面同时展示成交金额。默认显示最近 5 次交易，可继续展开。相同委托、ETF、买卖方向及交易日的分笔成交合并为一次展示，保留开始及最近成交时间，价格按成交金额／份额加权；不同委托不会混合。开仓、加仓、减仓、清仓和做 T 分类沿用成交流水。点击明细查看每笔成交的时间、价格、份额、费用、依据及持仓变化，点击 ETF 进入行情图表，「全部成交明细」直接展开下方成交页签。每 30 秒读取最近 200 笔成交，超过范围时标明汇总范围；更新失败提示缓存状态。该展示只读取成交，不把待执行委托或策略信号作为成交。

日 K 图在「我的 ETF」详情和策略信号页统一使用精简工具栏，仅常驻时间范围下拉框与「图表设置」入口。均线、成交量、MACD、价格行为图层、策略关键价位及买卖点显示开关收进默认关闭的设置弹窗；副图切换、历史回顾入口、读数说明也在其中。分时图的附近点位和成交显示开关同样通过「图表设置」打开。设置收起不关闭已选指标，原有指标偏好继续保存；进入回顾后才显示逐日回顾控制，退出即收起。买点复盘、更多指标与基金资料默认折叠。

策略信号固定按「候选、入选、持仓」排列。候选为观察范围内尚未入选的 ETF，入选为策略目标；盘后入选展示满足次日参考条件的 ETF，仍需盘中确认。持仓独立读取账户实际正持仓，包含未入选或不在当前策略名单里的 ETF，显示持有及可卖份额；零持仓和待成交委托不计入。入选与持仓可重合，账户刷新后同步更新数量与列表。

手机上点按一行在该行下方展开图表，再点按同一行收起；同一时间只展开一只。图内可切换分时与日 K，收起时卸载并停止对应轮询。总览的指定 ETF 链接会展开对应标的；不在当前分类的标的及上证指数临时放在列表顶部并标注「当前查看」，不增加栏目。桌面继续使用列表与图表双栏。

策略信号页提供候选、入选、持仓列表及各标的信号与最近模拟成交；ETF 详情与策略页的日 K、分时图共用紧凑成交标记：红色 B 表示开仓、橙色 B 表示加仓、蓝色 S 表示减仓、绿色 S 表示清仓；绿色 T 表示做 T 卖出、红色 T 表示做 T 买回。B/S/T 均为无背景、无边框、无阴影的彩色字母，保留 22 × 22 像素的点击区域，图例使用相同文字样式。灰色小号“m”表示复盘触价候选。成交标记优先避让，通过实心锚点及连线定位，连线止于字母区域边缘。点击标记或图下成交卡片，可查看每笔成交的时间、交易价、份额、费用、决策原因及成交前后持仓。

成交分类读取完整持仓流水（包含拆分份额变动），在成交列表分页前计算。同一笔开仓委托的分批成交均归为开仓；持仓不为零时新增买入委托归为加仓。卖出成交后仍有持仓表示减仓，实际持仓归零才表示清仓，不提前把未完成的卖出标为清仓。分类缺少可靠持仓流水时使用中性灰色 B/S，不猜测。日 K 同日同类成交合并，开仓／加仓、减仓／清仓分别保留。

成交接口通过 `order_kind` 返回原始委托类型，`t_sell` / `t_buy` 且成交方向一致时显示 T；普通盘中买卖或同日往返不会自动算作做 T。T 卖出、T 买回和普通 B/S 分开聚合，未成交的做 T 委托不显示成交标记；底层 `position_effect` 与持仓份额仍按流水计算。

5 分钟做 T 的买回支撑、卖出压力和失效价直接以虚线叠加在上述分时图内，不再单独显示状态面板。每 15 秒读取只读 `/t-strategy`，活动轮次使用冻结值，悬停图内标签查看行情来源和执行等待原因。worker 对今日已卖出清仓的 ETF 继续采集真实分钟 K，点位接口返回零持仓的观察参考价；无活动轮次时返回 `observation_only=true`，不会标为 T+1 等待解锁或触发买回委托。采集使用两个线程按最近尝试轮转，跨日后清仓标的自动退出观察范围。仅在 ETF、交易日及完整 K 时间与分时对应时显示，刷新失败移除旧参考价；参考价不会生成成交标记。总览分时卡片展示账户当前持仓及北京时间今日实际卖出的 ETF；今日清仓仍保留，持仓与今日卖出按代码去重，更早已清仓的隐藏。今日日期优先使用服务端时间，卖出记录沿用最近成交读取范围；跨日后不再保留昨日已清仓卡片。部分卖出或 T+1 暂不可卖的持仓仍展示，筛选不依赖做 T 开关或状态接口。没有持仓及今日卖出时显示空状态，历史成交日仍可选择，成交时间线和完整明细保留所有历史记录。仅修改此类展示时，运行 `docker compose up -d --build --no-deps --wait dashboard`，保持 worker 运行。

ETF 日 K 直接追加当日实时蜡烛柱，每 10 秒读取后台最新行情；使用来源报告的开盘、最高、最低、最新价及累计量额，不从第一笔分时或成交价推测开盘。价格按上一交易日的前复权收盘价／行情昨收转换，基准日期或价格未对齐时不拼接。界面展示行情时间，不加“未收盘”标签；缺失、异常或旧交易日行情不伪造当日 K。均线、成交量及 MACD 随当日柱更新，价格行为和策略依据继续使用已完成日线，实时柱不写入历史行情表，也不参与后台决策。回顾模式移除当日实时柱，收盘历史同步后同日只保留一根正式 K 线。

日 K 的买卖标记按成交日标在 K 线下方或上方，包括今日实时柱，日线前复权坐标不直接套用原始成交价。若对应日 K 因行情缺失或历史未齐而暂时无法显示，主图上方保留已成交卡片，展示方向、日期、笔数、份额与原始成交均价，点击可看明细；“今日”按最近一次成功读取成交记录的 UTC+8 日期判断。分时线与买卖标记共用 UTC+8 时间坐标，保留来源提供的秒数，分钟来源保留其原始精度。标记按成交时间定位在已有连续曲线上，午休按交易时间压缩并连接正常衔接的上午、下午行情；同一分钟同类成交合并，标签与详情保留数量加权的实际成交均价。标签为避免重叠可移动，连线始终指向曲线上的时间位置；缺少连续行情的成交保留图下明细。盘后候选不作为已成交展示。回顾模式隐藏回顾日之后的成交标记与时间轴记录。

成交展示每 30 秒检查更新，按当前 ETF 读取最近 200 笔；超出时提示总数，完整明细仍在投资总览。查询与展示不创建委托、不修改策略参数或交易账本。

投资总览主记录区仅保留「当前持仓、委托记录、成交明细」三个页签。「分红与折算」位于默认收起的「账户详情」内，展开时加载，收起后停止刷新。该列表只展示与账户持仓相关的事件，不直接列出基金全部历史公告。分红按权益登记日结束时的持仓流水筛选，已登记的分红权益和应收金额始终保留；卖出后才到账也属于账户记录。折算按生效日前的持仓和实际份额变动筛选，清仓后仍保留此前参与的折算。筛选在最近 200 条限制之前执行，只影响只读列表，不删除基金事件或修改账户记账。
